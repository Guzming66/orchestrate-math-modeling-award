# CUMCM 格式与提交门禁

## 权威与版本

本页是 **2026-08-08 的历史核验笔记**，用于帮助规则审计员理解字段，不是 finalizer 的可执行规则源。每场比赛必须把当届官方页面/PDF 保存为工作区 artifact，记录哈希与核验步骤，并填写 `compliance/competition_profile.json`。初始化 profile 为 `unverified`；不得按年份继承本页数值。

1. 当届赛事官网通知、规则与题面；
2. 全国组委会发布的论文格式规范；
3. 当届报名和参赛须知、赛区补充要求；
4. 本文件与往届材料。

上级来源覆盖下级来源。每次 Stage 0、8、9 都重新访问并创建新的 profile 版本：

- 2026 参赛规则：<https://www.mcm.edu.cn/html_cn/node/9d8e511fe7a1447b35f53a82c908e2e0.html>
- 2026 论文格式规范：<https://www.mcm.edu.cn/html_cn/node/4cd596519c9eb9fbd866398f6df0caa3.html>
- AI 工具使用规定（2025 年试行）：<https://www.mcm.edu.cn/html_cn/node/eebcfb6dc37fd2de9603dc16026fdf01.html>
- 历年赛题：<https://www.mcm.edu.cn/html_cn/block/8579f5fce999cdc896f78bca5d4f8237.html>

现有 AI 工具使用规定为 2025 年试行文件，2026 参赛规则要求遵守该规定。开赛时仍须从“章程及规则”入口重新确认它是否仍为有效版本，并保存页面或 PDF、取得时间和哈希；不要从文件年份推断其继续生效。

## 2026 历史字段映射

- 使用白色 A4；上下左右页边距至少 2.5 cm。
- 纸质版前两页为承诺书和编号页；摘要专用页为第三页。
- 电子论文不得包含承诺书或编号页；第一页必须是摘要专用页。
- 摘要含标题和关键词，原则上不超过一页；从摘要页开始用阿拉伯数字连续页码，页脚居中。
- 正文紧跟摘要；不要目录；正文不超过 30 页。
- 正文之后为附录，附录页数不限。附录应列支撑材料文件，并包含全部完整、可运行的源程序；未使用程序时写明官方要求的说明。
- 摘要、正文、附录、文件名、文件夹名和文档属性均不得出现队员、学校或赛区身份。
- 所有他人或公开资料都要在正文标注，并按科技论文规范列入参考文献。
- 官方未统一规定字号、字体、行距和颜色；不要把模板默认值宣称为官方硬性要求。
- 电子论文为一个 PDF 或 Word 文件，建议 PDF，不压缩，大小不超过 20 MB。
- 支撑材料为一个 ZIP 或 RAR，不超过 20 MB；与论文分开提交。内容至少覆盖可运行源程序、自主查阅的数据和必要的大篇幅中间结果。
- 支撑材料内容必须与论文和附录清单一致，不包含承诺书、编号页、身份信息、密码、令牌或私钥。

## AI 使用

2025 试行规定对使用 AI 的队伍要求：

- AI 生成内容在正文相应位置标注，所用 AI 工具列入参考文献；使用本 Skill 或 Codex 即属于使用 AI，不能声称未使用。
- 支撑材料包含官方指定名称的 AI 工具使用详情 PDF，记录工具与版本、具体用途/环节、关键交互和采纳/人工修改情况。
- 队伍对原创性、真实性和准确性承担责任；需要人工复核 AI 参与内容与引用。
- 参赛队必须逐项人工审查并核实 AI 参与内容；故意隐瞒、虚假声明，或将未经必要人工核验的 AI 输出直接作为核心成果提交，可能被取消评奖资格。

AI 规则可能逐届变化。`ai_usage_ledger.csv` 用于把每次实质使用映射到正文锚点、工具引用、人工修改/核验和交互证据 artifact；最终器只执行 verified profile 中有快照与哈希支持的字段。

## 自动与人工门禁

| 检查项 | 自动检查 | 人工确认 |
|---|---|---|
| 由 `paper/main.tex` 直接构建 | 构建入口固定 | 无平行 Word/Markdown 正文 |
| 纸张、页数、大小、目录 | `competition_profile.json` + `pdfinfo` + 构建报告 | profile 的官方快照真实有效，赛区无补充要求 |
| 页边距 | LaTeX 模板参数与渲染检查 | 密集图表未侵入边距，参数与 profile 一致 |
| 摘要/前置页 | 模板页数标记 + profile 上限 | 摘要确有标题、关键词、方法和结果 |
| 匿名 PDF 元数据 | profile 要求为匿名时检查 Author | 题注、代码注释、路径、文件名和图片中无身份 |
| 引用与交叉引用 | 编译日志门禁 | 每条关键来源真实且正文使用 |
| 完整源程序 | 无可靠全自动判断 | 论文附录与支撑包均含同版本可运行代码 |
| 支撑包 ≤20 MB 且一致 | 另行检查归档大小和清单 | 干净环境复现、无凭据和身份 |
| AI 声明 | 仅在 verified profile 要求时检查开关和位置 | 三名队员核实用途描述真实 |
| AI 使用详情材料 | 仅在 verified profile 要求时直编并核对支撑清单 | 人工核对必填内容与实际使用一致 |
| 当届其他材料 | 无额外自动门禁 | 只核对官方明确要求的材料 |

## 提交顺序

1. 冻结代码、数据、随机种子和结果表；从干净目录复现。
2. 更新正文、摘要和附录清单；直接编译 LaTeX。
3. 运行 `validate_competition_profile.py` 和 `build_latex.py --mode submission`，修复所有 `errors`。
4. 渲染 PDF 全部页面，逐页检查裁切、重叠、缺字、公式、宽表、页码和匿名。
5. 填写匿名词表和 `support_manifest.json`，由 `package_submission.py` 从附录引用的同版本文件生成支撑 ZIP，并扫描身份、路径、元数据和凭据。
6. 当届规则要求额外说明时，按官方要求生成、命名和提交。
7. 由三名队员分别核对：规则/匿名、数值/复现、论文/附件；把 G0—G7 的复核人与证据写入门禁状态文件。
8. 运行 `finalize_submission.py`；上传后核对系统中的文件大小和最终清单哈希，不再修改对应文件。
