## 证据边界

本指南结合官方格式门禁与用户提供的 2022--2025 年 47 篇 CUMCM 优秀论文作结构校准。47 篇共 2379 页，已逐页执行原生文本提取或中文 OCR，源 PDF 与合并文本哈希均 47/47 通过；另按每篇 4 个关键页视觉核验 188 页。题目侧完整切分 2022、2024、2025 共 15 道题、56 个小题，并解析 113 条附件记录。完整方法、计数和限制见 [cumcm-corpus-evidence-2022-2025.md](cumcm-corpus-evidence-2022-2025.md)。

OCR 只用于章节、语言和证据职责信号；公式、精确数值、表格单元格和代码不能据此认定正确。样本不是完整获奖总体，任何出现率都不产生字号、摘要长度、图表数、章节数、模型选择或获奖概率阈值。

可迁移的观察是：摘要首页承担逐问结果地图；正文通常为单栏、层级克制的科技论文版式；有效图表直接支持几何、模型、结果或验证。不要复制展示论文的句子、具体解法、图片布局或模型名称。

## 最终论文保留什么

论文只呈现评委理解与核验解答所需的内容。内部研究和审计仍完整保存，但不进入正文。

| 内容 | 默认处理 |
|---|---|
| 标题、摘要、关键词 | 保留；摘要原则上独占第一页，具体页数服从 verified profile |
| 任务分析与小题关系 | 保留；用短文或一张关系图说明输入、输出、约束和依赖 |
| 假设、数据处理、符号 | 只保留会影响模型或结论的项目；合并为“建模基础” |
| 每个小题的模型、求解、结果、验证 | 保留；按小题形成闭环 |
| 全局稳健性或误差传播 | 仅在跨小题或改变结论时单列 |
| 局限与适用边界 | 保留具体边界；不写套话式优缺点清单 |
| 独立结论章 | 仅在能综合三问而非重复摘要时保留 |
| AI 声明、附录、支撑材料 | 只按 verified profile 的位置和形式加入 |
| 原题复述、长背景综述 | 删除；不得大段改写题面 |
| 候选池、失败调试、Agent 分工、评分表 | 留在 `innovation/`、`audits/` 和日志，不进论文 |
| artifact 路径、哈希、命令、内部 JSON/CSV 文件名 | 留在证据台账，不进论文 |
| freeze/验收、review status、claim status、下游接口等流程元语言 | 翻译成建模语言或删除，不进论文 |
| 完整代码 | 仅在 verified profile 要求的附录或支撑包出现 |

不要默认生成目录、致谢、获奖预测、评委口吻、自我评分、“创新点”口号页、装饰性技术路线或没有结果职责的流程图。

## 摘要与正文语言

### 摘要

按“任务 -- 方法职责 -- 核心结果 -- 最强可信证据/边界”写每个小题。背景通常不超过一至两句。每个核心数字必须来自 `result_manifest.csv`，带单位、比较对象或适用条件。语料中 43/47 篇出现逐问信号、40/47 篇出现定量结果信号、31/47 篇出现验证或误差信号；这是摘要信息职责的校准，不是强制句数或每问数字配额。

摘要不放公式推导、文献回顾、引用、代码过程、长模型清单、未运行的预期结果和空泛创新词。不要只写“效果良好”“精度较高”“具有现实意义”；改写成可追踪的指标、区间、约束满足情况或稳健边界。

### 正文

- 一段只承担一个论证职责：提出结构、定义变量、建立模型、报告结果或解释边界。
- 先写为什么需要该步骤，再给数学表达；不把算法名称当作理由。
- 用“计算得到”“在条件 X 下”“相对基线 Y 改善 Z”替代“容易发现”“显而易见”“充分证明”。
- “显著”“最优”“准确”“鲁棒”“有效”必须绑定统计检验、可行性证明、对照实验或明确指标。
- 统一使用题面术语、符号和单位；精度服从输入与不确定性，不保留无意义小数。
- 区分事实、假设、计算结果和解释。预测关联不写成因果，样本内结果不写成普遍规律。
- 少用连续的“首先、其次、然后、最后”。优先用因果、约束和变量关系连接句子。
- 不写“我们为了提高创新性引入……”；若题意直接规定完整对象，直接建立保真模型；只有额外复杂度才写明简化模型的局限和最小改变。
- 不写“本文不虚构置信区间”“本改动不作为创新”“Q1 验收后冻结”等否定性或流程性元话语。

标题优先概括对象、核心任务或关键机制，不堆叠算法名。关键词选择题目对象、任务类型和一至两个关键方法，避免“数学建模”“优化模型”等无区分度词语。

## 按小题组织正文

在 `paper/generated/question_sections.tex` 按实际小题数量载入独立文件：

```tex
\input{sections/questions/q01.tex}
\input{sections/questions/q02.tex}
\input{sections/questions/q03.tex}
```

每个小题文件按需要使用下列顺序，不机械生成空标题：

1. 任务与结构：本问输入、输出、约束、上游接口和评价锚点；
2. 模型：变量、目标、约束、关键机制和必要假设；
3. 求解：只写足以复现数学过程的算法和参数；
4. 结果：给出核心数值、单位、现实含义和对题目的直接回答；
5. 验证与边界：基线、诊断、消融、误差、敏感性或反事实中真正需要的部分；
6. 复用：用竞赛原生语言说明后续问题沿用的判据、数值、单位、不确定性和适用范围。

验证优先紧跟相应结果。进入下一问前检查本问是否已经直接回答题目，并且所有显式表格、结果文件和下游接口都有对应产物；不能只在算法介绍处结束。只有多问共享同一风险时，才创建 `06_global_validation.tex`。只有存在跨问综合或具体失效条件时，才创建 `07_synthesis_and_limits.tex`。

## 科研图表

有源数据的量化图优先使用 `$scipilot-figure-skill`：先明确本图要支持的论文论点，剖析样本量、缺失、分布、异常和分组结构，再选图、按最终尺寸绘制并完成程序自检与 PNG 读图回改。`$data-analytics:visualize-data` 用于交互探索、通用设计和第二视角 QA。机理、几何、流程、网络与算法示意图不交给 SciPilot，使用可复现 TikZ/Graphviz/原生代码；SciPilot 不可用时直接使用 Matplotlib/Seaborn 并执行同等检查。

CUMCM 中文图默认从 `setup_style(journal='general', lang='zh', use_sciplots=False)` 开始，再按已核验模板调整栏宽与字体；只有预览和最终 PDF 证明 SciencePlots 样式没有额外刻度、字体或版面问题时才启用。样式名不能替代当届格式核验。

每幅图必须登记一个主要证据职责：`mechanism`（机理/几何/流程）、`data`（数据结构与质量）、`diagnostic`（误差、基线、消融、不确定性或稳健边界）或 `decision`（结果、策略与行动区域）。一图可以提供次要信息，但不得用多个模糊目的逃避主职责；没有职责的图删除。

当正文的核心判断依赖空间几何、视线、遮蔽、可见性、投影、碰撞、坐标系或轨迹关系时，必须先安排一幅 `mechanism` 直观图；结果曲线不能替代它。图中至少同时呈现两个关键对象或关系，并与公式使用同一符号、坐标方向和边界定义。优先画“对象—关系—判据”，不要画照片、装饰性技术路线或与求解无关的三维效果。若确实不需要机理图，在 `paper_payload.json` 写明不适用理由。

- 保存原始数据、变换、绘图脚本、随机种子和输出哈希。
- 量化图先运行数据剖析并记录选图理由；小样本不得用裸均值柱隐藏原始点，分类变量不得用折线暗示连续关系，连续色阶必须带有单位的 colorbar。
- 按最终 LaTeX 尺寸渲染预览，检查缺字、裁切、刻度重叠、图例遮盖、子图编号、跨图尺度和数据完整性；发现问题回到源代码修改并重渲，不手工 P 图。
- 优先输出矢量 PDF；栅格图只用于无法矢量化的内容，并在最终尺寸检查分辨率。
- 轴名、图例和题注写清变量、单位、样本量及区间含义；CI、SD、SE 或分位区间不得混称“误差”。
- 颜色之外再使用线型、点型、填充或直接标签；检查灰度可辨性。
- 比较图保持相同尺度；柱状图通常从零开始；对数轴、截断轴、平滑、归一化和缺失值处理必须说明。
- 避免装饰性 3D、渐变背景、阴影、饼图堆叠、雷达图和双纵轴；只有数学语义需要时例外。
- 表格承载精确查数，图形承载结构、趋势或比较；不要同时重复同一批数字。
- 在 LaTeX 最终栏宽查看字体、线宽、图例、裁切和色彩，不以单独打开图片的效果代替版面检查。
- 若全局坐标范围把关键差异压缩到不可见，使用局部放大、inset、相对坐标或删除；图形必须让评委直接看到所支持的结构或比较。
- 通过视觉闭环后再导出，并运行 SciPilot 的 `check_figure.py --strict`；字体嵌入若仅为 warning，再用 `pdffonts` 独立复核 `emb=yes`，不得凭 warning 或单一检查器直接放行。最后仍须把图嵌入 LaTeX 编译后的整页 PDF 复核。

题注先说明对象和编码，再给读图所需的条件；正文解释结论，不在题注重复整段分析。

## 终审问题

1. 摘要能否在 30 秒内回答每个小题的方法、结果和可信依据？
2. 是否存在大段题面复述、长背景或没有参与模型的符号和假设？
3. 每个公式、表格和图片是否支持一个正在使用的论点？
4. 是否把内部候选、任务、Agent、路径、哈希或验证器名称写进正文？
5. 每个强形容词是否能替换为具体数字、区间、基线或边界？
6. 每问是否直接回答题目，而不是在算法说明处结束？
7. 结论、评价和摘要是否在重复同一组数字？若是，保留信息最完整的位置。
8. AI 声明、附录和支撑材料是否只按 verified profile 出现？
9. 完整代码、全量中间表和文件清单是否留在 profile 指定的附录/支撑包，而不是挤占正文？若 profile 明确要求代码进入论文附录，是否保持同版本且可运行？
10. 是否把远小于输入/模型误差的求解器位数写进正文，造成伪精确？
11. 数学定义与代码实现之间的边界、消元、离散或端点假设是否已证明、解释或独立验证？
12. 依赖几何、轨迹或可见性的小题，是否有一张评委可在 10 秒内看懂对象与判据的直观图？
13. 所谓“独立复算、证书、收敛或稳健”是否在纸面给出了比较对象、配置、误差或边界，而不是一句断言？
14. 渲染后的页面是否存在由浮动体漂移造成的大面积空白、图文断裂或空标题？
