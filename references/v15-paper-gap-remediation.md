# v15 论文差距整改与验收说明

## 目标

本轮整改针对“总控生成稿与国赛展示论文之间仍有明显成稿差距”这一问题。目标不是机械增加页数、模型或图，而是让每个小问在最终论文中形成可核验的完整论证：题意与定义清楚、关键推导可跟随、答案直接、证据充分、边界诚实、图形承担明确职责，并且内部总控语言不会泄漏到正文。

## 主要差距与设计判断

| 差距 | 风险 | v15 判断 |
|---|---|---|
| “强基线、冻结、验收、证书”等总控词进入论文 | 评委看到的是工作流说明而不是数学论证 | 内部词只留在控制平面，正文必须翻译为具体模型、局限、实验或推导 |
| 小问篇幅短但真正缺的是推导、比较与边界 | 机械页数下限会诱发题面复述和套话 | 不设页数配额；按任务、模型/推导、直接结果、验证/边界四类职责和论文锚点验收 |
| 验证压缩成“结果一致、模型合理” | 无法判断比较对象、误差或适用范围 | 每问绑定最强验证锚点；独立审查的 pass 必须记录具体攻击、结果和真实 artifact |
| 几何题只有结果曲线或抽象公式 | 空间对象、方向、边界和判据难以在短时间内理解 | 几何债务按主张登记；高视觉负荷必须提供可复现 mechanism 图和十秒读图结论 |
| 图在脚本窗口可读、缩进论文后失效 | 标签过小、局部结构被压扁、过绘掩盖信息 | 所有图绑定实际 LaTeX 宽度，并由审阅人声明最终字号与最终尺寸复核；量化图再声明样本/像素与过绘保真，不能把这些人工记录误称为自动测量 |
| 摘要或结论使用“首次、全局、最优”等强措辞 | 局部搜索被误写为全域结论 | 模型冻结后先人工建立结果级清单；论文中的常见措辞由有限正则哨兵提示漏项，每次已登记出现再绑定完整定义域、覆盖策略、排除论证和 artifact；validator 不宣称完备发现或替代数学证明 |
| 未载入草稿能帮助门禁通过，或动态 TeX 输入绕过扫描 | 审计对象与最终 PDF 不一致 | 文字审计只看 `main.tex` 的静态、工作区内 TeX 输入闭包；构建再用 `.fls` 实际输入反查，任何闭包外本地 TeX 都阻断 |
| 赛事规则按年份猜测，或只检查字段非空 | 过时格式要求可能被误执行 | verified Competition Profile 强制有效生效起点、官方来源定位和证据哈希，主文件固定为 `paper/main.tex` |
| 复现命令能清理输入或依赖人工中间步骤 | 结果不可恢复或存在破坏风险 | 入口文件与哈希绑定，只允许参数数组；清理仅限命名输出目录，终审在隔离副本实际重跑 |

## 已实施的核心改动

1. Paper Payload 升至 schema v4。每问必须登记直接答案、最强验证、复杂度必要性、精度策略、逐条几何主张和图稿最终尺寸。
2. Review Findings 升至 schema v3。每个 required review 的通过记录必须绑定本问论文锚点、具体检查、实际证伪或边界攻击、检查结果与 artifact 哈希，不能复制通用通过理由。
3. 新增强全域主张证书。模型冻结后先完成 `global-claim-draft` 人工结果清单；论文成文与复现后再逐出现位置覆盖，并按离散候选、连续搜索、事件搜索和混合策略路由不同的证明责任。自动词表只作已加载 TeX 的有限漏项哨兵。
4. 强化独立小问交付。独立 PDF 必须同时具有任务、模型/推导、结果、验证/边界四类实质内容；比较性验证必须有评委可见的表或图；多页稿末页异常稀疏会阻断。
5. 强化整篇 PDF 复核。构建报告记录每页正文上下边界、下方空白比例、词数和被排除的页脚词数；稀疏页只能在确属结尾材料或结构分页时作具体处置，PDF 或指标变化会撤销复核。
6. 强化几何与科研制图。高负荷几何主张必须绑定 mechanism 图；所有图由审阅人确认最终标签字号至少 6 pt，并把声明宽度与真实 LaTeX 栏宽核对；有源量化图优先使用 SciPilot 完成数据剖析、选图和读图闭环，机理图仍由 TikZ、Graphviz 或原生代码生成。
7. 强化文字、来源闭包与相似度。阻断控制平面术语、聊天残留和相邻中文重复；只扫描最终静态加载来源，并用 TeX `-recorder` 的 `.fls` 反查实际本地 `.tex`，闭包外输入不放行；对已登记的优秀论文 OCR 与固定模板执行可解释的规范化字符重合预检。
8. 强化规则、任务、依赖和迁移。verified profile 必须有有效生效起点；preflight 把 CLI 静态契约与当前 Python 的运行依赖分开诊断；workflow v15 按模型冻结后的强主张草案、论文写作、逐位置认证、复现和终审排序；v8–v14 迁移保留科学产物，但重开已经改变语义的展示、审查和复现信任状态。

## 论文深度的验收原则

v15 不把“页数多”当成“内容充分”。正文是否需要扩展，只看缺失的论证职责：

- 定义或假设是否足以推出模型；
- 关键公式是否说明来源、变量和适用域；
- 算法是否交代输入、约束、停止准则及与数学模型的对应；
- 每问是否给出题目要求的直接数值、判据、方案或文件；
- 最强验证是否报告比较对象、配置、误差、敏感性或边界；
- 结论是否说明会改变决策的限制与不确定性；
- 几何关系是否能通过公式与图在十秒内对应。

缺哪一项就补哪一项，不用题面重述、算法名堆叠、泛化优缺点或装饰图填充页面。因此，一个短而闭合的小问可以通过；一个页数较多但没有推导或验证的稿件仍会阻断。

## 验收范围与边界

- 自动门禁验证结构、来源身份、哈希、加载闭包、可复现性和表达责任，不自动证明数学定理、文献主张或赛事获奖水平。
- 当前公开实现的工程证据属于 E0；历史赛题端到端盲评仍属于后续 E1/E2 评估。
- 现有 PDF 不会因 Skill 更新自动改变。必须在 v15 工作区重新完成 Payload、审查、图稿和 LaTeX 构建，才能体现本轮整改。
